## 검토 중 발견해 수정한 문제

- 처음에는 범위 밖 질문에 인접한 TX-credit 내용과 다른 테스트의 PASS를 답했다.
  명시적 제외 범위를 로컬에서 판별해 외부 호출 없이 거절하도록 했다.
- 0-credit 복구 질문에서 FCT 조건을 누락하거나, 0-credit 차단 테스트가 복구를
  검증한 것처럼 표현했다. Spec 발췌를 우선하고, 테스트 질문이 아니면 Golden
  시나리오·Test·run 증거를 전달하지 않도록 했다.
- 출력의 `[G1:626–629]`, `[G1,G2]` 형태 인용은 ID만 정규화하고 허용된 근거
  ID인지 확인한다. 테스트 근거가 없는 질문에서 테스트/PASS 주장은 거부한다.
- E2-2에서 첫 답변은 유효한 인용이 없어 거부됐다. 허용 ID를 명시한 뒤 재검증에서
  정상 답변을 받았다.

## 남은 한계

- 범위 검사는 명시적 용어에 기반한다. 새로운 표현이나 여러 항목을 섞은 질문은
  추가 표본 검토가 필요하다.
- 근거 ID 검사는 출처의 존재를 확인하지만 문장과 출처의 의미 관계를 자동 판정하지
  않는다. 기술 정확성은 이번 10문항에서 수동 확인했다.
- 질문 유형에 따라 테스트 근거를 선택하는 규칙은 키워드 기반이다. 우회 표현으로
  테스트 결과를 묻는 경우에는 근거가 빠질 수 있다.
